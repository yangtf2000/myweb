B · 应用说出这段 Python 在干什么6 分钟

下面这段，用一句话说清它做什么，再说 nums 最后变没变。

nums = [3, 1, 4, 1, 5, 9, 2, 6]
top = sorted(nums, reverse=True)[:3]
print(top)
看解答

取这组数里最大的三个，降序打印：[9, 6, 5]。

nums 没变。sorted 是排完给你一个新的，原列表不动；nums.sort() 才是排它自己，但那个方法返回 None，写成 top = nums.sort() 会得到 None —— 第 05 章会讲这个坑。

判断的规矩：要留原数据用 sorted，不要了用 sort。

先换向量化。pandas 和 NumPy 的批量操作在底层是连续内存上的整块运算，通常能把几十秒压到一两秒，改动量只有几行，风险最小。

Python 用换行断语句、用缩进划范围，不写分号也不写大括号。这套做法的代价是什么？如果代码要压缩成一行（比如 minify），Python 会怎样？

看解答

代价是排版即语义：改缩进就改了程序的行为，而且复制粘贴时最容易出错。收益是可读性强 —— 代码长什么样，结构就是什么样，不用数括号。

另一个代价是没法靠排版自由换行：一条语句想拆成两行，得用反斜杠，或者把内容放进括号里 —— 括号内的换行是自由的，这一点写长表达式时很有用。

压缩成一行时，Python 用分号分隔语句（a=1; b=2 合法），但复合语句（if、for、def）不能用分号压，语法上不允许。所以 Python 几乎没有 minify 这回事，要靠打包工具而不是压缩源码。

顺带一句：Python 允许用 \ 续行，但更推荐在括号里换行 ——括号内的换行是自由的，这一点很多人不知道，写长表达式时很有用。

看解答

19.99 * 3 * 0.8 在 Python 里得 47.976000000000006。会计上应该得 47.98（按分四舍五入）。

差的 0.000000000000006 看着微不足道，但累加到几万笔订单，就会和账面对不上。财务系统里这类差异必须为零，差一分都要查。

根因是二进制浮点无法精确表示 0.1、0.2、19.99 这类十进制小数 —— 就像十进制无法精确表示 1/3。这和第 3 行的 0.1+0.2 是同一件事。

from decimal import Decimal, ROUND_HALF_UP
p = Decimal('19.99')
total = (p * 3 * Decimal('0.8')).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
# Decimal('47.98')

f-string：拼字符串就用它

早年的写法是 "%s 有 %d 岁" % (name, age)，后来是 "{} 有 {} 岁".format(name, age)。这两种在老代码里到处都是，遇到了要认得，但自己写一律用 f-string，在字符串前面加一个 f，花括号里直接放变量：

python
name = "杨子禺"
age = 11

print(f"{name} 有 {age} 岁")
print(f"明年他 {age + 1} 岁")          # 花括号里可以直接算
print(f"身高 {1.23456:.2f} 米")         # 保留两位小数
print(f"|{name:>8}|")                   # 右对齐，宽度 8
print(f"|{name:<8}|")                   # 左对齐
print(f"及格率 {0.8732:.1%}")           # 百分比，87.3%

记住 f 这个前缀，忘了它，花括号会原样打出来。冒号后面是格式说明，.2f 两位小数、.1% 百分比、>8 右对齐八格，够用。

C · 思考为什么 join 比 + 快10 分钟

把一万个短字符串拼成一个长串，用 += 循环和用 join，耗时差多少量级？从内存分配的角度解释原因。

看解答

实测差 两到三个数量级（一万个片段大约 0.1 秒对 0.001 秒）。

原因是分配次数。+= 每次都新建一个字符串：第 1 次复制 1 个片段，第 2 次复制 2 个，……第 n 次复制 n 个，总共复制约 n²/2 个片段。一万个就是五千万次字符复制。

join 先算出总长度，一次分配，然后把每段拷进去，总共复制 n 个片段。复杂度 O(n)。

所以规则很简单：已知要拼很多段，就收集到列表再 join。只有拼两三段时，f-string 或 + 更清楚，也够快。

顺带一句：CPython 对 s += x 有一个优化 —— 如果引用计数为 1，它会原地扩容。所以在简单循环里它可能没那么慢，但这个优化不保证在所有实现里都有，不能依赖。

这是 Python 最值得先学会的一招。把“遍历、判断、收集”三件事写成一行：

a = [1, 2, 3, 4, 5]

推导式
a = [1, 2, 3, 4, 5]
b = [x * x for x in a if x % 2 == 0]
print(b)      # [4, 16]

结构是 [对每个元素做什么 for 元素 in 序列 if 条件]。读的时候从中间往两边读：“对 a 里的每个 x，如果 x 是偶数，就收下 x 的平方”。

一个列表里装着字典：rows = [{'a': 1}, {'a': 2}]。用 rows[:] 复制一份，改新列表里第一个字典的 a，原列表会变吗？为什么？怎么才能真正独立？

看解答

会变。rows[:] 是浅拷贝：新建了一个外层列表，但里面的元素仍然是原来那些字典对象的地址。所以改 new[0]['a']，改的是同一个字典，原列表当然看得到。

三层概念要分清：

赋值 b = a：一个新名字，零个新对象。

浅拷贝 a[:] / a.copy() / list(a)：新建外层容器，内部元素共享。

深拷贝 copy.deepcopy(a)：递归复制所有层，完全独立。

用哪个看需求：只是要一个能独立增删的列表（不改元素内容），浅拷贝够；要改元素本身，必须深拷贝。深拷贝慢，元素多的时候注意。

顺带一句：不可变对象不用担心这件事。列表里装的全是整数、字符串时，浅拷贝和深拷贝效果一样，因为元素改不了。

    count[w] = count.get(w, 0) + 1
# {'a': 3, 'b': 2, 'c': 1}

第二种：

from collections import defaultdict
count = defaultdict(int)
for w in s.split():
    count[w] += 1

第三种：

from collections import Counter
count = Counter(s.split())
print(count.most_common(2))  # [('a', 3), ('b', 2)]

C · 思考为什么在循环里删列表元素会漏12 分钟

a = [1, 2, 2, 3, 2]，想把所有的 2 删掉。写成 for x in a: if x == 2: a.remove(x)，结果是什么？为什么？给出两种正确写法。

看解答

结果是 [1, 2, 3] —— 还剩一个 2。而且这个结果依赖具体位置，换个排列可能剩两个。

原因是边遍历边改长度：for 内部维护一个索引，删掉一个元素后，后面的元素整体前移一位，索引却继续往后走，于是跳过了一个。

两种正确写法：

① 倒着删，因为删除只影响后面的元素：

for i in range(len(a) - 1, -1, -1):
    if a[i] == 2:
        del a[i]

② 重建列表（更 Python）：

a = [x for x in a if x != 2]

② 更好，因为它不改变原列表（除非你赋值回去），也不用想索引。如果要原地改：a[:] = [x for x in a if x != 2]。

顺带一句：字典也一样，遍历时增删会抛 RuntimeError，要先 list(d) 复制键再遍历。这类“遍历中修改”的错误，在任何语言里都要小心，Python 的好处是它会直接报错（列表不会报，更阴）。

必须记住的坑

默认值不要写成可变对象。下面这个函数，你以为每次都从空列表开始，其实共用同一个：

def add_item(x, box=[]):      # 错
    box.append(x)
    return box

print(add_item(1))   # [1]
print(add_item(2))   # [1, 2]  不是 [2]

默认值只在函数定义时算一次，之后每次调用都用那一个对象。正确写法是默认给 None，进去再建：

def add_item(x, box=None):
    if box is None:
        box = []
    box.append(x)
    return box

def add(item, box=[]):
    box.append(item)
    return box

print(add('a'))
print(add('b'))
print(add('c', []))
print(add('d'))
看解答

['a']

['a', 'b']　（同一个默认列表）

['c']　（显式传了新列表，用的是新的）

['a', 'b', 'd']　（又回到那个默认列表，它现在有 a、b、d）

第三行最容易判断错：它看起来“重置”了，其实什么都没重置 —— 只是这一次用了调用方新建的列表。

修法：

def add(item, box=None):
    if box is None:
        box = []
    box.append(item)
    return box

注意用 is None 而不是 == None，也不要用 if not box —— 后者会把传进来的空列表也当成没传，语义就变了。

C · 思考函数改了传入的列表，算不算 bug12 分钟

写一个函数，参数是一个列表，函数里对它排序后返回。调用方的列表也变了。这是 bug 吗？该怎么设计才不让人意外？

看解答

不是 bug，是设计选择，但很容易让人意外 —— 这本身就是问题。

两种设计都有人用，关键是命名和文档要让调用方知道：

① 原地修改，返回 None。学 list.sort() 的做法，函数名用动词短语（sort_in_place），并且明确返回 None，这样调用方不会写成 a = f(a)。

② 不改输入，返回新对象。学 sorted() 的做法，函数里先 data = list(data) 复制一份再操作。这是更安全的默认。

一般建议选 ②，除非性能真的重要（大列表复制很贵）。理由是“函数不改变输入”是一条能让人放心组合的规则：你不用读实现，就知道调用它之后自己的数据还在。

顺带一句：这条规则在 NumPy 上不成立 —— NumPy 的切片是视图，很多函数默认原地改。所以用 NumPy 时要格外注意 copy()。

04小结与延伸Recap10 分钟
一条主线

默认参数只在 def 执行的那一刻求值一次，之后一直复用那个对象。所以 def f(x, box=[]) 里的 [] 是一个列表，所有没传 box 的调用共享它。正确写法是 box=None，函数里再 if box is None: box = []。

想一次给出好几个结果，直接返回多个值就行，Python 会把它们打包成一个元组，调用方再按顺序解包。return lo, hi，调用时 lo, hi = f(a)。所以“一个函数只能返回一个值”在这里不是约束。

1参数顺序：位置参数 → 默认参数 → *args → 仅关键字参数 → **kwargs。用 * 可以把后面的参数强制成关键字传。
2*args 收成元组，**kwargs 收成字典。调用时用 * 和 ** 拆开，这两个方向都要会。
3不要在函数里改传入的列表/字典，除非你明确就是要改。改之前先 copy 一份，否则调用方会发现自己的数据变了。

C · 思考为什么循环导入难修12 分钟

A 导入 B，B 又导入 A。为什么 Python 会报错，而不是像“只把声明抄进来”那样处理掉？两种修法各适合什么场合？

看解答

因为 Python 的 import 是执行，不是声明。导入 B 的时候，B 的代码要真的从头跑一遍。跑到一半发现需要 A，而 A 还在等 B 跑完 —— 于是 A 在 sys.modules 里只是个空壳，拿它的属性就报错。

两种修法：

① 抽公共模块（首选）。A 和 B 都要用的东西，抽到 C，A 和 B 都只依赖 C，依赖关系变成单向。这解决的是设计问题，不只是报错。

② 延迟导入。把 import B 从文件顶部挪到函数内部，等到真正调用时才导入，那时 B 已经加载完了。这招快，但用多了会让依赖关系变模糊，只适合“确实只在某个函数里用一次”的场合。

判断标准：如果两个模块互相需要对方的数据结构，说明它们本来就是一个模块，该合并；如果只是某几个函数互相调用，抽公共层。

total = 0
with open('data.txt', encoding='utf-8') as f:
    for line in f:
        parts = line.strip().split(',')
        if len(parts) < 3:
            continue
        total += int(parts[2])
print(total)

顺手多加了两处防护：strip() 去掉行尾换行，len(parts) 挡住坏行。真实文件里总有坏行。

C · 思考写文件怎么保证不丢数据12 分钟

程序要把 10 万行结果写进 out.csv，过程中可能断电或被 kill。直接 open('out.csv','w') 写有什么风险？怎么改才安全？

看解答

两个风险。一，'w' 一打开就把原文件清空，如果这次运行失败，旧数据也没了。二，写的内容在缓冲区里，不 flush 不落盘，进程被杀就丢一截。

安全做法是三步：

① 写临时文件 out.csv.tmp，原文件全程不动。

② 写完 flush() + os.fsync()，强制落盘。只 flush 不够，flush 只是从 Python 缓冲交给操作系统，操作系统还有一层缓存。

③ 用 os.replace('out.csv.tmp', 'out.csv') 原子替换。这个操作在同一个文件系统内是原子的 —— 要么旧的完整，要么新的完整，不会出现半个文件。

这套写法叫“写时复制 + 原子替换”，所有正经的数据库、配置管理工具都这么干。代码只多三行，但避免了“跑了两小时，结果文件是空的”这种事故。

B · 应用写一个不会出现负余额的账户类15 分钟

要求：Account(owner, balance=0)；有 deposit(n) 和 withdraw(n)；取款超过余额时抛 ValueError；金额不许是负数；print(a) 要打出一句人话。

看解答
class Account:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError('初始余额不能为负')
        self.owner = owner
        self._balance = balance

    def deposit(self, n):
        if n <= 0:
            raise ValueError('存款金额必须为正')
        self._balance += n
        return self._balance

    def withdraw(self, n):
        if n <= 0:
            raise ValueError('取款金额必须为正')
        if n > self._balance:
            raise ValueError(f'余额不足，当前 {self._balance}')
        self._balance -= n
        return self._balance

    def __repr__(self):
        return f'Account({self.owner!r}, {self._balance})'

    def __str__(self):
        return f'{self.owner} 的账户：{self._balance} 元'

几个要点：校验写在方法里，不写在调用方（这是类的意义）；余额用 _balance 表示内部；__repr__ 让人在调试时能直接看到值，而不是 <Account object at 0x7f...>。

注意 {self.owner!r} 里的 !r 会调用 repr，效果是给字符串加上引号，这样 Account('张三', 100) 一眼能看懂。

看解答

迁到另一个时区后，历史数据的含义变了：同样一个字符串，在新时区被解释成另一个绝对时刻。所有“按时间排序”“算时长”“查某天订单”都会错，而且错得不明显 —— 数字都在，就是不对。

正确做法：

① 存 UTC（或带时区偏移的 ISO 8601，如 2026-10-17T02:30:00+00:00）。绝对时刻唯一，没有歧义。

② 显示时再转。用户在东八区就显示东八区，换个用户换一种显示，数据不动。

③ 记录时区。如果业务本身依赖“当地几点”（比如营业时间），那要单独存一个时区字段，不能靠猜。

Python 里用 datetime.now(timezone.utc) 拿当前 UTC 时间，用 astimezone() 转本地。注意 naive 和 aware 不能直接相减，会抛 TypeError —— 这个报错其实是在帮你。

01导论与概述Context10 分钟

NumPy 的数组和 Python 列表不是一回事：它是一块连续内存，元素类型统一，外加一套描述“怎么跨步取下一个元素”的信息。所有运算都是整片做的：a + b 是整个数组相加，底层是编译好的循环，还可能用上 SIMD。

所以用 NumPy 的核心原则只有一条：不要写 Python 循环。任何“对每个元素做点什么”的需求，先想能不能写成整片运算。能写成的，快几十上百倍；写不成的，才退回循环。

本节重点
  1. 1NumPy 数组类型统一、内存连续，所以快。切片是视图，改一个另一个也变 —— 这一点和列表相反。
  2. 2整片运算不用循环：a * 2 + 1 直接对每个元素做。写循环就慢几十倍。
  3. 3广播规则两条：从右往左对齐，维度相等或其中一个是 1 就能广播。

广播

形状不一样的两个数组，NumPy 会试着“拉平”成能算的形状。二维数组加一维，等于每一行都加上那一行：

python
m = np.array([[1, 2, 3],
              [4, 5, 6]])
row = np.array([10, 20, 30])

print(m + row)
# [[11 22 33]
#  [14 25 36]]

# 每列减去该列的均值（中心化），这是标准操作
print(m - m.mean(axis=0))

一条主线

视图和副本是 NumPy 最容易出错的地方。切片返回视图（共享内存），花式索引（用列表或布尔数组取）返回副本。所以 a[0] = 9 会改原数组，a[a > 5] = 9 也会改（这是赋值给索引），但 b = a[a > 5] 之后改 b 不影响 a。要明确复制就写 .copy()。

广播不复制数据，它只是让形状对得上。(3,1) 和 (4,) 相加，前者被“看成” (3,4)（每行重复），后者被“看成” (3,4)（每行一样）。内存里没有真的复制，所以省。但结果会分配一个新数组，那个是实打实的。

1造数组：np.zeros、np.ones、np.arange、np.linspace、np.random.default_rng()（新的随机接口，别用 np.random.rand）。
2统计沿轴：a.sum(axis=0) 是沿着行方向压，得到每列的和。记不住就想“axis=0 意味着第 0 维消失了”。

C · 思考groupby 之后为什么常常接 reset_index12 分钟

df.groupby('品类')['金额'].sum() 的结果是什么类型？为什么很多人后面接一个 .reset_index()？不接会怎样？

看解答

结果是一个 Series，索引是品类名，值是和。它不再是 DataFrame，而是“一列数据 + 一个索引”。

不接 reset_index() 会有三个后果：

① 不能按列名取。result['品类'] 会报 KeyError，因为“品类”在索引里，不在列里。要取得用 result.index。

② 写 csv 时第一列没有表头，或者多出一列叫“index”。

③ 不能继续 merge。merge 要按列合并，索引对不上。

reset_index() 把索引变回普通列，得到一个规整的 DataFrame：两列，一列叫“品类”，一列叫“金额”。

顺带一句：用 as_index=False 可以一步到位 —— df.groupby('品类', as_index=False)['金额'].sum() 直接返回 DataFrame。这比后面接 reset_index 更清楚。

一条主线

pandas 的索引有两套：位置索引（第几行）和标签索引（索引值）。.iloc 用位置，.loc 用标签。切片时 .iloc[0:3] 取 0、1、2（含头不含尾，和列表一样），.loc['a':'c'] 取 a、b、c（含尾，和列表不一样）。这个不一致是历史遗留，只能记。

① 想说“两者几乎一样” —— 纵轴从 0 开始。柱子几乎一样高，结论一目了然。

② 想说“B 略高” —— 别用柱状图，用点图或者直接标数值。柱状图天生不适合表达微小的相对差异。

C · 思考这个 bug 怎么三十秒定位12 分钟

程序跑了十分钟，输出是空的，也没有报错。你会按什么顺序查？每一步要得到什么信息？

看解答

按“从结果往前倒”的顺序，四步：

① 确认输入。打印读进来的数据条数。如果是 0，问题在读，不在算 —— 路径错、编码错、分隔符错，三种可能。

② 确认中间结果。在处理链的中间打一个计数，看在哪一步变成 0。这一步能砍掉一半代码。

③ 确认输出。如果中间有数据、最后没有，问题在写：可能是覆盖写（'w' 开了两次）、写到了别的路径、或者结果在缓冲区没 flush。

④ 确认没被吞掉。搜一遍代码里有没有 except: pass。有的话临时改成 except Exception as e: print(e)，错误会自己跳出来。

这四步的共同点是每一步都在缩小范围，而不是“猜哪里可能错”。猜是最慢的办法，因为它不产生信息。

C · 思考第二档：这份数据脏在哪18 分钟

给你一个 csv，读进来发现：某列有空值、某列数字被存成字符串、有些行的字段数不对、日期格式有 2026/10/17 和 2026-10-17 两种。写出清洗的步骤顺序，并说明为什么是这个顺序。

看解答

正确顺序是：先修结构，再修类型，最后处理缺失。

① 结构：先处理字段数不对的行。因为它们会让后面所有按列取值的代码崩溃，或者悄悄错位。做法：读的时候用 on_bad_lines='skip' 跳过并记数，或者用 csv.reader 自己按 len(row) 过滤。

② 类型：把日期统一成一种格式（pd.to_datetime(..., format='mixed') 或者 errors='coerce' 把解析失败的变 NaT），把数字列转成数值类型。

③ 缺失：这时才处理空值。因为前两步会产生新的缺失（解析失败的日期变 NaT），如果先处理缺失，前两步又会引入新的。

顺序错了会怎样？先处理缺失，再转类型 —— 转换失败的值又变成缺失，得再处理一遍。每改一次数据都要重新检查缺失，会反复三遍。

还有一条经验：清洗过程要留痕。每一步删了多少行、改了多少值，都记下来，最后打一张“清洗报告”。否则过一周你自己都不知道数据是怎么变少的。

C · 思考为什么“学完再做事”是错的12 分钟

很多人想“等我把 Python 学扎实了再做项目”。这个想法的问题在哪？给出一个替代的做法。

问题在于“扎实”没有终点。Python 的标准库有二百多个模块，第三方库几十万个，永远学不完。而且没有项目牵引，你不知道该学哪个 —— 学了 re 的高级语法，结果你的项目根本不需要正则。

替代做法是“项目牵引，缺什么补什么”：

① 定一个具体的小目标（比如“把这份 csv 变成一张图”）。

② 直接动手，卡住就查。查到的知识因为“当场要用”，记得比看教程牢。

③ 做完回头看一遍代码，把重复的部分抽成函数，把难懂的地方加注释 —— 这一步才是真正的“学扎实”。

有个说法很准：你写的第二个项目，才会用上第一个项目学到的东西。所以第一个项目丑一点没关系，重要的是做完。
